## Что это

**DataStudio** — Spring Boot 3.3.3 / Java 21 + статический фронт на ванильном ESM (без сборки). Форматирование/валидация **JSON** и **XML**, анализ **логов** (извлечение/нормализация/дедуп JSON-сообщений). Архитектура `controller → service → util → model` для текущего масштаба адекватна — **переусложнять не нужно**.

## Карта кода

- **Backend:** `controller/{FormatController,LogsController,ApiExceptionHandler}`, `service/{Json,Xml,Log}Service`, `util/{JsonBalancer,HashUtil,JsonUtils,XmlUtils,UniversalJsonExtractor}`, `model/*` (record-DTO). XXE-защита в `XmlUtils.parseSecure`. Лимиты в `application.yml`.
- **Фронт:** `static/js/{core/{api,dom,highlight,router,theme,strings,i18n}.js, tools/{json,xml,logs}.js, main.js}`. Все русские UI-строки — в `core/strings.js`; разметка через `data-i18n`/`-ph`/`-title` (`i18n.applyI18n`). Состояние логов приватно в `tools/logs.js`. Темы на CSS-токенах (`data-theme`).

## Принципы разработки

- **Сначала тест, потом рефакторинг** — особенно для парсинг-логики (обработку логов трогать только под тестами).
- **Пропорциональность масштабу** — без абстракций «на вырост»; стратегии/модули вводить, когда появляется третий случай.
- **Один источник правды** для дублирующейся логики (скобки, хеш, формат экспорта, ключ `value`, UI-строки).
- **Безопасность по умолчанию** — пользовательский контент в DOM только через эскейп; CORS не `*` на проде.
- **Коммиты/деплой — по запросу владельца** (см. память `formatter-conventions`).
- **Не глотать ошибки** — логировать (slf4j).

## Backlog — рост функционала (после тестирования)

> Копилка идей. Конкретику и приоритеты обсуждаем отдельно. Каждый новый формат = отдельный `*Service` + ветка диспетчера; при 3-м+ формате — реестр стратегий `Map<String, FormatStrategy>` (НЕ микросервисы).

Приоритетно (по интересу владельца):
1. **GraphQL** — pretty/валидация запросов и SDL-схем, просмотр операций. Вероятно, самый востребованный следующий формат.

Прочие кандидаты:
2. **Форматы:** YAML, CSV/TSV (+конвертация JSON↔YAML, CSV↔JSON), возможно TOML/`.properties`.
3. **Утилиты:** JWT-декод, Base64, URL-encode, разворачивание escape-строк, хеши.
4. **Diff:** структурный diff двух JSON/XML (есть база — каноникализация и хеши).
5. **Валидация по схемам:** JSON Schema, XSD.
6. **Анализ логов по уровню/ошибкам (INFO/DEBUG/ERROR).** Сейчас логи только извлекают JSON; семантического анализа нет. Чтобы фильтры INFO/DEBUG/ERROR заработали, бэкенд должен возвращать `level`/`traceId`/тип в модели item (сейчас в item нет `raw`, `level` всегда INFO; работают только request/response/internal/external по `key`). Фильтр в UI оставлен как задел.

**От ассистента ожидается:** предлагать конкретные расширения с оценкой сложности/риска и вписывать их так же осторожно и инкрементально, как стабилизацию.
