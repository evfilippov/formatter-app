# Тестирование

Два независимых уровня:

## 1. Бэкенд (Java / JUnit) — есть
Maven-тесты сервисов и утилит. Запуск (основной способ — Docker):
```
docker compose run --rm test
```
Локально также работает `mvn test`. На 2026-05-30 — 41 тест, зелёные.

## 2. Фронтенд E2E (Playwright) — добавлено 2026-05-30
Реальный браузер (Chromium) открывает приложение и проверяет клики/флоу по разделам.
**Dev-only:** на поставку приложения не влияет — фронт остаётся статикой без сборки.

### Установка (один раз)
```
npm install
npx playwright install chromium
```
> `npx playwright install` скачивает браузер (~пара сотен МБ) — разовая операция.

### Запуск
Приложение должно быть поднято на http://localhost:8080:
```
docker compose up --build -d      # если ещё не запущено
npm run test:e2e                  # прогон тестов
```
> Конфиг (`playwright.config.js`) переиспользует уже запущенный сервер; если он не
> поднят — Playwright сам стартует контейнер и дождётся порт.

Полезное:
- `npm run test:e2e:ui` — интерактивный UI-режим (удобно отлаживать).
- `npm run test:e2e:headed` — видимый браузер.
- `npm run test:e2e:report` — открыть HTML-отчёт после прогона.

### Что покрыто (e2e/)
- `navigation.spec.js` — карточки главной, переключение разделов сайдбаром, смена темы.
- `json.spec.js` — Pretty, Minify, «Числа → value».
- `xml.spec.js` — Pretty.
- `logs.spec.js` — извлечение → переход на результат + карточка + traceId, «Назад к вводу», фильтрация поиском.

Новый раздел/формат = новый файл `e2e/<раздел>.spec.js` (как и модули в `static/js/tools/`).

### Подсказка про вход логов в тестах
`LogService.parseMultipleLogEntries` начинает **новую запись с каждой строки, которая
начинается с `{`**; прочие строки приклеиваются к текущей записи. Поэтому «одно
сообщение на строку» для тестов делается так: каждая строка начинается с `{`, но не
является валидным JSON — тогда это TEXT-запись и срабатывает regex-паттерн, напр.:
`{ internalRequest = {"id": N, "name": "nN"} }`. Разный `id` → нет дедупликации.
