# Тестирование

Два независимых уровня:

## 1. Бэкенд (Java / JUnit) — есть
Maven-тесты сервисов и утилит. Запуск (основной способ — Docker):
```
docker compose run --rm test
```
Локально также работает `mvn test`. На 2026-05-30 — 41 тест, зелёные.

## 2. Фронтенд E2E (Playwright) — добавлено 2026-05-30
Реальный браузер (Chromium) открывает приложение и проверяет клики/флоу по разделам.
**Dev-only:** на поставку приложения не влияет — фронт остаётся статикой без сборки.

### Установка (один раз)
```
npm install
npx playwright install chromium
```
> `npx playwright install` скачивает браузер (~пара сотен МБ) — разовая операция.

### Запуск
Приложение должно быть поднято на http://localhost:8080:
```
docker compose up --build -d      # если ещё не запущено
npm run test:e2e                  # прогон тестов
```
> Конфиг (`playwright.config.js`) переиспользует уже запущенный сервер; если он не
> поднят — Playwright сам стартует контейнер и дождётся порт.

Полезное:
- `npm run test:e2e:ui` — интерактивный UI-режим (удобно отлаживать).
- `npm run test:e2e:headed` — видимый браузер.
- `npm run test:e2e:report` — открыть HTML-отчёт после прогона.

### Что покрыто (e2e/) — быстрый дымовой набор
- `navigation.spec.js` — карточки главной, переключение разделов сайдбаром, смена темы.
- `json.spec.js` — Pretty, Minify, «Числа → value».
- `xml.spec.js` — Pretty.
- `logs.spec.js` — извлечение → переход на результат + карточка + traceId, «Назад к вводу», фильтрация поиском.

Новый раздел/формат = новый файл `e2e/<раздел>.spec.js` (как и модули в `static/js/tools/`).

## 3. Полный UI-прогон (e2e-full/) — добавлено 2026-05-30
Исчерпывающий «прокликивающий» набор: **каждая кнопка и действие** во всех разделах
на тестовых JSON/XML/логах со всеми условиями обработки. Цель — после крупного блока
работ быстро увидеть регрессии. Гоняется **не каждый раз** (экономия токенов/времени),
а по готовности большого блока.

```
npm run test:ui-full
```
Особенности (заданы в проекте `ui-full` в `playwright.config.js`):
- **браузер обязателен** (`headless: false`) — видно вживую;
- **замедление** `slowMo: 550 мс` между действиями — можно уловить шаги глазами;
- 1 поток (`--workers=1`), окно 1440×900, выданы права на буфер обмена.

38 тестов в 4 файлах:
- `01-navigation.spec.js` — сайдбар (все разделы + активный пункт), карточки главной, тема.
- `02-json.spec.js` — Pretty/Minify/Validate (валид + сломанный), пустой ввод, копировать/скачать, файл; режим Value Wrapper: Wrap/Unwrap/«Числа → value», переключение режима.
- `03-xml.spec.js` — Pretty/Minify/Validate, escape→`result.txt`, пустой ввод, копировать, все опции-чекбоксы, файл.
- `04-logs.spec.js` — анализ→результаты (статистика/график/traceId), фильтры по типу (точные счётчики) и уровню, сортировки, поиск+счётчик+история, regex-поиск, подсветка, флаги уникальные/дубликаты, карточки (сворачивание, звезда, копировать/скачать), сравнение (карточки и тулбар), экспорт, общий отчёт, Ctrl+G, навигация, сброс.

> ⚠️ Грабли, заложенные в тесты:
> - `validate` (JSON/XML) возвращает `output: null` — **success-уведомления нет**;
>   сигнал корректности — пустой/непустой блок `#…Errors`.
> - Чекбоксы `regexMode`, `showOnlyUnique`, `showDuplicates` живут на **странице ввода**
>   (`#logs`), скрытой на результатах → выставлять их нужно **до** анализа.
> - Звезда карточки видна только при `:hover` → перед кликом навести курсор.
> - Дубликаты бэкенд в `items` не отдаёт (`duplicateOf` всегда `null`), уровень лога
>   тоже не приходит — фильтр ERROR/DEBUG → пусто.

### Подсказка про вход логов в тестах
`LogService.parseMultipleLogEntries` начинает **новую запись с каждой строки, которая
начинается с `{`**; прочие строки приклеиваются к текущей записи. Поэтому «одно
сообщение на строку» для тестов делается так: каждая строка начинается с `{`, но не
является валидным JSON — тогда это TEXT-запись и срабатывает regex-паттерн, напр.:
`{ internalRequest = {"id": N, "name": "nN"} }`. Разный `id` → нет дедупликации.
