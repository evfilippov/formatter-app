**Стабилизация и модернизация ЗАВЕРШЕНЫ (Phases 1–5).** Приложение **в тестировании** (владелец + коллеги, ~1–2 недели) — новый функционал сейчас не добавляем, ждём фидбэк. **Дальше:** по итогам тестирования — backlog (ROADMAP «Backlog»: GraphQL — приоритет, далее YAML/CSV, утилиты, diff, схемы; отдельно — анализ логов по уровням).

### Как проверить состояние
1. Запуск из исходников: `docker compose up --build -d` → http://localhost:8080 (Ctrl+Shift+R для сброса кэша). Или из Docker Hub: `docker run --rm -p 8080:8080 e1vg/datastudio:latest`.
2. Backend-тесты: `docker compose run --rm test` — **42 теста**.
3. E2E: `npm run test:e2e` (быстрые, headless) · `npm run test:ui-full` (полный, видимый браузер). Установка один раз: `npm install` + `npx playwright install chromium`. Подробно — [TESTING.md](./TESTING.md).

### Phase 5 — Подготовка фронтенда + редизайн 🔄 (2026-05-30)

**Этап D — визуальный редизайн ✅ (в основном сделан, принят владельцем):**
- Новая дизайн-система на CSS-токенах: тёмная тема по умолчанию + светлая (`data-theme`), палитра «сланец + пыльный индиго», переключатель темы в сайдбаре. Файл `styles.css` переписан целиком.
- Левый **сайдбар-навигация** вместо верхнего меню (масштабируется под будущие форматы). Приложение переименовано **Formatter → DataStudio** (видимый бренд; имя docker-образа пока не менялось).
- Главная упрощена (карточки Logs/JSON/XML). JSON/XML: короткие описания; **поля ввода и вывода равны и выровнены** (макет `io-layout`: поля в ряд, действия под ними); единый файловый пикер с состоянием.

- **Подсветка синтаксиса JSON** (`syntaxHighlightJson`, токены `tok-*`) в выводе логов и JSON-форматтере; яркая красная подсветка поиска.

- **Новая функция:** в JSON (режим Value Wrapper) кнопка **«🔢 Числа → value»** — собирает JSON-массив `{"value":"<n>"}` из набора чисел (любой разделитель, value строкой). Полностью на клиенте.
- В план (ROADMAP §15) добавлена идея владельца: **анализ сообщений по уровню/ошибкам** (INFO/DEBUG/ERROR/internal), а не только извлечение JSON. Сейчас фильтры по типу (request/response/internal/external) работают по `key`; INFO/DEBUG/ERROR неактивны (бэкенд не возвращает `level`/`raw`).
