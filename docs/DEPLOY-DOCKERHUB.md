## 2. Подготовка к Docker Hub

Текущий `Dockerfile` уже хороший: multi-stage (build на `maven:3.9-eclipse-temurin-21` → runtime на `eclipse-temurin:21-jre`), `EXPOSE 8080`, `HEALTHCHECK` на `/actuator/health`, лимиты памяти через `JAVA_OPTS`. Ниже — что подготовить перед публикацией.

### 2.1. Аккаунт и репозиторий
- Создать аккаунт на hub.docker.com; создать репозиторий, напр. `<username>/datastudio`.
- Решить: **public** (открытый) или **private**.
- Создать **Access Token** (Account Settings → Security) и логиниться им, а не паролем.

### 2.2. Гигиена перед сборкой (рекомендуемые правки репозитория — по согласованию)
- [ ] **Добавить `.dockerignore`** (сейчас его НЕТ). Исключить из контекста сборки: `target/`, `node_modules/`, `e2e/`, `test-results/`, `playwright-report/`, `.git/`, `*.md`. → быстрее сборка, меньше контекст.
- [ ] **Запуск не от root** в runtime-образе (добавить непривилегированного пользователя + `USER`). Безопасность.
- [ ] **OCI-метки** в Dockerfile: `org.opencontainers.image.title/description/source/version/licenses`. Красиво и информативно на Hub.
- [ ] (Опц.) Spring Boot **layered jar** для лучшего кэширования слоёв.
- [ ] Убедиться, что `/actuator/health` включён (от него зависит HEALTHCHECK).
- [ ] Конфиг наружу через **env** (CORS origins, лимиты) — чтобы образ настраивался без пересборки.
- [ ] Завести **версионирование** (тег образа = версия приложения, напр. из git-тега).

### 2.3. Сборка и публикация
```bash
docker login -u <username>
# тег = версия + latest
docker build -t <username>/datastudio:1.0.0 -t <username>/datastudio:latest .
docker push <username>/datastudio:1.0.0
docker push <username>/datastudio:latest
# проверить опубликованный образ
docker run --rm -p 8080:8080 <username>/datastudio:1.0.0   # → http://localhost:8080
```

### 2.4. Мульти-арх (опционально, для Mac/ARM)
```bash
docker buildx build --platform linux/amd64,linux/arm64 \
  -t <username>/datastudio:1.0.0 --push .
```
`buildx` идёт в комплекте с Docker Desktop.

### 2.5. Качество и безопасность образа
- **Скан уязвимостей** перед пушем: `docker scout cves <username>/datastudio:1.0.0` (Docker Scout встроен).
- Никаких секретов в образе (только через env при запуске).
- README/overview на странице репозитория Hub: что это, порты, env-переменные, пример `docker run`.

### 2.6. На будущее (опционально)
- **CI/CD**: GitHub Actions, который собирает и пушит образ по git-тегу `v*`.
- Подписать образы (cosign) — если нужна проверяемость.

## 3. Каталог инструментов: что нужно и когда

**Нужно для текущего проекта (всё уже есть):**
Java 21, Maven, Docker + Compose, Node.js + npm (E2E Playwright), Git, VS Code.

**Полезно/опционально сейчас (есть в комплекте Docker, ставить отдельно не надо):**
- Docker Scout — скан образов; Docker Buildx — мульти-арч сборка.
- VS Code расширения: Extension Pack for Java, Playwright Test for VSCode, Docker, ESLint/Prettier.

**Ставить ТОЛЬКО когда появится конкретная потребность (сейчас НЕ нужно):**
- **PostgreSQL** — если добавим серверную персистентность (сохранение логов/настроек/пользователей).
- **SQLite** — лёгкая встраиваемая БД как альтернатива Postgres.
- **uv / pip-инструменты** — если заведём Python-утилиты в проекте (сейчас Python — только разовые скрипты, `python -m pip` достаточно).
- **GitHub CLI (`gh`)** — для автоматизации релизов/CI.
- **jq** — удобная обработка JSON в шелле (необязательно).

> Принцип: окружение расширяем под конкретную задачу, а не «на всякий случай».
